# Audit: Tier 6 — `swebench/` + `programbench/` + `benchmark/` + `eval/` + `testgen/`

Status: **DONE** · Updated 2026-05-29 · 63 files / 11,230 lines · substantive files read in full, boilerplate bulk-read

## What it does
The accuracy-measurement + test-generation tier. **`benchmark/`** runs public SWE-bench instances through the **real production pipeline, blind**; **`swebench/`** is the superseded oracle adapter (sandbox plumbing reused); **`programbench/`** reimplements binaries in cleanroom containers; **`eval/`** is the offline model-evaluation framework (per-tier × provider, regex + LLM-judge scoring); **`testgen/`** is the parallel test-generation pipeline (plan → generate → compile → execute).

## Findings — uniformly well-built; the headlines are an accuracy lever + a superseded adapter to delete.

### Accuracy / efficiency (ties directly to the Codex/Claude-Code goal)
- 🔵 **`benchmark/` correctly measures the real system, blind** (honours `feedback_benchmark_real_system`). It submits `runMode=BUILD, source="swebench-codegen"` → the REAL classifier→planner→worker path (the system picks its own SINGLE_SHOT/SMALL/… strategy), stopped at the worker by an orchestrator code-gen-only gate **before the reviewer** (so the captured `git diff` is a clean minimal patch — the reviewer's 469-line `PostEditFormatter` whole-file reformat + scaffolding + auto-commit would otherwise pollute it). The agent is **blind** — sees only the issue `problem_statement`, never `FAIL_TO_PASS`/gold `test_patch` (applied at scoring time, outside the agent) → leaderboard-comparable. The gate is tightly scoped to the benchmark source; every production run is byte-identical full-pipeline.
- 🔵 **The empirical miss mode IS the accuracy lever.** First blind Live run (2026-05-24, Sonnet) = ~45% resolved, dominant miss = **under-scoping multi-file changes** (the `benchmark/CLAUDE.md` "actionable scaffold lever"). This is the concrete thing to improve to meet/beat Codex/Claude Code on the same blind set (RL-2026-05-050's harness-improvement track: better localization tools + higher iteration budget + reproduce-first/minimal-diff discipline, landing in the real product). Pair this with the [validator.md](validator.md) incremental-build-gate lever.
- 🟡 **`swebench/SwebenchTaskService` (736) + the old `SwebenchController` are a SUPERSEDED oracle adapter** — bypassed the production entry point AND injected the gold `test_patch` into the prompt (oracle setting → non-publishable; its old 67%/60% numbers are discarded). Only its sandbox plumbing (`SwebenchProperties`/`InstanceLoader`/`ContainerStore`) is still reused by `benchmark/`. The `benchmark/CLAUDE.md` explicitly queues it for **removal** once `benchmark/` is the validated default. Dead-once-cutover code to delete (~800 LOC).

### Security (🟢 — sandboxing is strong)
- 🟢 **Cleanroom containers are properly isolated.** SWE-bench/ProgramBench/benchmark all `docker run --rm --network none -v <workspace>:/testbed` (network-isolated — matches SWE-bench eval semantics + prevents the agent pulling deps). `testgen/HeadlessTestExecutor` runs LLM-generated tests in a **hardened** container: `--rm --network=none --memory=2g --cpus=2 --read-only --tmpfs /tmp --security-opt no-new-privileges --cap-drop ALL -v …:ro`. The CLAUDE.md "containerized test execution" claim is real and well-implemented.
- 🟢 **All admin harness controllers are gated** — `swebench`/`programbench`/`eval`/`eval/v2` are `/api/admin/**` + `@PreAuthorize("hasRole('SUPER_ADMIN')")`; `benchmark` too. `testgen/TestResultController` (`/api`) is **run-access-guarded** (`runAccessGuard.requireRunAccess`). No gating gaps.
- 🟢 **No cost-tracker bypasses** — testgen + eval route LLM calls through `FallbackLlmRouter`/`LlmRouter` (cost-tracked), unlike the [codeintel.md](codeintel.md)/[assessment.md](assessment.md) direct-`anthropicModel.call` holes.
- 📝 `testgen/TestCompilationGate` runs `mvn test-compile` **host-side** (ProcessBuilder, not containerized) on LLM-generated test code — compile-only (execution IS containerized), so low risk, but a malicious Maven plugin could execute during the compile phase. Minor.

### Operational robustness (🟢, from `benchmark/CLAUDE.md`)
- 🟢 Hard-won hardening documented: skip `docker pull` when image present (a present-image pull still round-trips the registry + timed out under load → froze runs); workspace must live outside macOS TCC-protected `~/Documents` (else the JVM loses disk access mid-run → worker freezes); `status_reason` VARCHAR(80) truncation on setup-failure; best-effort `preds.json` capture on wall-timeout (was the silent-uncaptured "16→15" artifact). `BenchmarkGenerationService` (lean synchronous `/generate`, no `submitRun`/async/credits) is compile-verified but **not yet runtime-tested** — the Live run used the older `submitRun` path.
- 🟢 `eval/` is offline admin tooling: `ModelEvaluator` (per-tier × provider), `EvalScorer` (regex + dimension scoring), `LlmJudgeValidator` (Haiku second-pass judge for saga tests), `TierEvalRunner` (v2 — drives the real agent prompts + tool schemas through `LlmRouter`, scores tool-call validity / cache-hit / latency / cost). Clean.
