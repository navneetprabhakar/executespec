# ExecuteSpec — Agentic v2 (frontend A/B alternate)

> Side-by-side alternate UX. Lives at `/a/*` routes; the existing v3 shell
> at `/home`, `/projects/:id`, `/runs/...` stays untouched. The user can
> toggle between them via the avatar menu. After the test the user picks
> the keeper; the loser deletes cleanly (one directory + one route block).

## Design thesis

ExecuteSpec is **agentic by architecture** — a pipeline of LLM agents that
plan, code, test, review, and ship PRs. The current v3 chrome treats it as
a console with tabs and dashboards. That hides the agent.

**v2 thesis:** the agent is the product. Every surface frames work as a
conversation with an autonomous coding partner that already knows your
codebase. Tabs become threads. Dashboards become activity streams. Status
becomes presence.

## Apple-HIG-aligned principles (non-negotiable)

1. **One anchor per screen.** Large title, then content. No multi-column
   chrome competing with the title for attention.
2. **Direct manipulation.** Tap an item to act on it. Swipe to dismiss /
   archive. Long-press for context.
3. **Sheets, not pages.** Auxiliary actions surface as bottom sheets that
   spring up; full-page navigation is reserved for content changes.
4. **Continuous gestures.** Swipe right to go back. Pull to refresh.
5. **Calm typography.** JetBrains Mono everywhere (per user requirement).
   Weight + size + opacity carry the hierarchy.
6. **Spring motion.** All transitions use spring physics with a single
   shared duration token.
7. **Reversibility.** Every destructive action has an undo or a confirm.
8. **Accessibility-first.** Every status is colour + icon + text.

## Voice

Confident, calm, technical. Active verbs. No marketing fluff on utility
surfaces. Examples:

| Don't say                                | Say                                |
| ---------------------------------------- | ---------------------------------- |
| "Every PR you've shipped, in one place." | "Recent · 12 runs · 3 active"     |
| "What do you want to build?"             | "Tell the agent what to do."       |
| "Your AI assistant is ready."            | "Agent ready."                     |
| "Pluggable solutions that adapt…"        | "28 solutions · 4 categories"      |

```
│ ◀ ●─────────  workspace ▾  ··· │ ← Top bar (52px)
├────────────────────────────────┤
│                                │
│ Large title                    │
│ Status line                    │
│                                │
│ [content]                      │
│                                │
│                                │
├────────────────────────────────┤
│ ┌──────────────────────────┐   │
│ │ Ask the agent…       ↑   │   │ ← Persistent agent input
│ └──────────────────────────┘   │   (slides up on scroll)
├────────────────────────────────┤
│  🏠     ✦     📚     🙂        │ ← Bottom nav (60px)
│  Home  Activity Catalog You    │
└────────────────────────────────┘
```

Bottom nav: 4 slots, identical shape, active = filled glyph + pill on top.

### Desktop (≥ 1024 px)

```

├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│                  Large title                                        │
│                  Status line                                        │
│                                                                     │
│  ┌────────────────────────────────────────────────────────────┐    │

│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
                              ↑
                       Floating agent input pinned bottom-center,
                       same shape as mobile, expands on focus into

```

## Surface map (full coverage)

| Route                       | Component             | Shape                                          |
| --------------------------- | --------------------- | ---------------------------------------------- |
| `/a/home`                   | `HomePage`            | Agent hero + activity stream + quick-jump tiles|
| `/a/projects/:id`           | `ProjectPage`         | Agent thread for this project + side rail      |
| `/a/runs/:id`               | `RunPage`             | Verdict-first mission control                  |
| `/a/library`                | `LibraryPage`         | App-Store gallery: featured + categories       |
| `/a/migrations`             | `MigrationsPage`      | Gallery sibling                                |
| `/a/settings`               | `SettingsPage`        | iOS-grouped list with anchored sections        |
| `/a/billing`                | reuse v3 BillingPage  | (functionality preserved; future iteration)    |
| `/a/pricing`                | reuse v3 PricingPage  | (functionality preserved; future iteration)    |
| `/a/login` `/a/register`    | reuse existing auth   | (forms are already fine)                       |
| `/a/admin/*`                | reuse v3 admin pages  | (admin density is fine for the use case)       |

The reuse is intentional — auth + admin + billing already work well; the
v2 thesis is about the daily-driver surfaces (home, project, run, catalog,
settings).

## Mounting + toggle

- `App.tsx` adds `<Route path="/a/*" element={<AgenticShell/>}>` block.
- `AvatarMenu` gets a new "Try the new UI" item that navigates to
  `/a/home`. Mid-session toggles preserve auth state (shared store).
- A symmetric "Back to classic" item in the v2 user menu navigates to
  `/home`.

## What's preserved

- Every Zustand store, every API client call, every SSE subscription.
- Every entitlement gate, every tier paywall.
- JetBrains Mono font (per user requirement).
- Graphite + Signal palette (continuity).
- No backend file changes.

## What changes for v2 users

- Default landing for `/a/home` is the agent input, not the dashboard.
- Project view is thread-first; tabs become section anchors.
- Run detail leads with verdict + score + 2 actions; numerics live under
  disclosure.
- Library / Migrations are App-Store-style galleries (no marketing copy).
- Settings is iOS-grouped (no flat scroll).

## After the A/B

- If v2 wins: delete `frontend/src/v3/`, `frontend/src/pages/project/`,
  promote `/a/*` routes to `/*`.
- If v3 wins: delete `frontend/src/agentic/` and the `/a/*` route block.
- Either way: clean removal in a single commit.
