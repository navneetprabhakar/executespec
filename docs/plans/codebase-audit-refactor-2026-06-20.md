# Codebase Audit + Refactor Register

> Status: active register for the post-launch code audit/refactor track.
> Parent context: user-requested full repo audit after the agent-control-plane/API work is tested.

## Scope

Audit the current ExecuteSpec repo for consolidation, duplication, drift, and maintainability risk,
then refactor in bounded slices with tests and documentation in the same change.

This register is separate from the web-agent / managed-AI launch plan. Launch work can continue
there; this file tracks the broader code-quality pass.

## Coding Profile Guardrails

Apply the saved Navneet coding profile:

- keep controllers thin and delegate into services
- prefer straightforward service/helper extraction over framework-heavy abstractions
- keep typed DTOs and explicit status/reason/cost fields
- consolidate repeated policy/action metadata into one source of truth
- add tests at the owning seam: controller contract, service policy, helper unit, frontend parser/UI
- preserve ExecuteSpec's stricter conventions: constructor injection, records where already used,
  Flyway/package docs, and focused behavior tests

## Audit Lanes

| Lane                    | What to inspect                                                                     | First evidence target                                                        |
| ----------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Agent control plane     | action catalog, intent routing, orchestrator confirmation, stream event contract    | no duplicated action metadata; local-vs-cloud actions stay explicit          |
| Managed AI              | model classification, budget state transitions, notification dedupe, per-call debit | step-up/down rules are isolated and testable                                 |
| Frontend agent shell    | `IdeAgent`, agent API client, project/run chat migration                            | reducer/control-plane state stays testable and not hidden in ad hoc booleans |
| Billing legacy services | large service methods, duplicated top-up math, analytics TODOs                      | extract helpers only where risk is covered by tests                          |
| Documentation drift     | plan/status docs, terminal audit register, package `CLAUDE.md` files                | stale gaps are corrected as implementation lands                             |
