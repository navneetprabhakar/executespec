## 🔴 HIGH — ship next

### H1 — Plan 2 Gap 2 Phase 2 · V2 startup full replay

Load `v2:agent-ctx:{runId}:{taskId}` from Redis on boot; rehydrate worker
history; resume `WorkerAgentV2` at the saved iteration instead of marking
interrupted `WORKING` / `REVIEWING` runs FAILED (Phase 1 + 1.5 shipped).

- **Size:** ~400 LOC.
- **Scope:** `StartupRunResumerV2`, new `WorkerAgentV2.resumeFromSnapshot`, integration test using JVM-stop fixture.
- **Perf risk:** boot latency +200 ms – several seconds per orphan run. 3-attempt cap (Phase 1.5) prevents infinite replay. Keep replay async — do not block actuator/health.
- **Blocked on:** nothing. Ready to start.

### H2 — Bug #1c · `ModelResolver.selectAdaptiveProvider` bypasses strict-provider

Adaptive routing silently switches providers even when
`-Dexecutespec.strict-provider=true`. Evidence: Proj-OpenAI (74270ac6) logged
`provider=anthropic` despite `project.aiProvider=OPENAI`. Fix: strict-mode
guard inside `resolve()` OR opt-out flag per org.

- **Size:** ~30 LOC + test.
- **Perf risk:** fix BLOCKS legitimate failover when the chosen provider is down → user runs 503 instead of silent success on fallback. Arguably correct behaviour under strict mode; document clearly.
- **Blocked on:** nothing.

### H3 — Plan 5 P0 · batch-API probe across 3 providers

One batch submission per provider with native tool calling; confirm response
shape + measure p50 latency; document verdict in
`docs/v2-batch-probe-notes.md`.

- **Size:** probe + doc, no prod code.
- **Perf risk:** external spend $5–10 + up to 24 h wait. Zero steady-state impact.
- **Blocked on:** user approval to spend.

## 🟢 DEFER — ship only when triggered

### D1 — Plan 3 · Preview control-plane gRPC daemon (all 3 phases)

Separates preview VM pool from app JVM via gRPC + mTLS. Brand-new infra:
cert rotation, `preview_session` + `preview_vm` tables, scheduler, lease
service, 25 % canary, eventual Docker-mode retirement.

- **Size:** ~2 500 LOC + infra.
- **Perf risk when landed:** +10–50 ms per preview start/stop (gRPC vs
  in-process). Offsetting positive: app JVM GC pauses don't stall running
  previews.
- **Trigger to start:** preview resource contention on app node (CPU / memory
  headroom) OR multi-region preview requirement. Neither today.

### D2 — Plan 4 · RAG memory-overflow vector spill (was "Item 1")

When a project's compacted snapshot crosses 12 K tokens, spill the oldest
compacted block to `project_document` (`source=MEMORY_OVERFLOW`) and truncate
the snapshot.

- **Size:** ~150 LOC + snapshot-rewrite edge cases.
- **Perf risk:** spilled chunks add to pgvector search space → retrieval
  cost per planner call grows **O(N)** with project age. Needs a retention
  policy (e.g. spill-source eviction after M months).
- **Trigger:** first project reports `MAX_MEMORY_TOKENS` pressure.

### D3 — Plan 4 · RAG OCR / rerank / semantic chunking (was "Item 3")

- **OCR:** Tika already OCRs when Tesseract is on PATH. No-op today.
- **Rerank:** one LLM call per retrieval. +$0.001–0.005 per planner call.
  Latency +500 ms – 2 s per retrieval.
- **Semantic chunking:** one-time per-doc cost; no hot-path impact.
- **Trigger:** observable retrieval-quality regression. None today.
