# Terminal Audit Register

> Status: active audit register for terminal / CLI / VS Code work.
> Parent launch plan: [`agent-control-plane-managed-ai-2026-06-19.md`](agent-control-plane-managed-ai-2026-06-19.md).

This document separates terminal work from web-agent and managed-AI work so it can be audited without reading the whole launch plan.

## Audit Rule

Any change that affects the terminal experience, CLI behavior, VS Code local-hands behavior, local shell/git/file execution, terminal streaming, permission prompts, or the server APIs those clients consume must carry one of the `TERM-AUDIT-*` tags below.

Use the tag in:

- issue title or task title
- PR description
- commit body when practical
- test report or QA handoff
- reason-log entry when the change is architectural or user-visible

Do not hide terminal items under generic `WEB`, `AGENT`, `BILLING`, or `MANAGED-AI` labels.


## Review Checklist

For each terminal-tagged change, verify:

- The tag matches the actual owner repo.
- A client-side UI/local-action change is not mixed into a server-only PR unless it is only documentation or contract coordination.
- A server contract change is backward-compatible or has an explicit migration note for CLI and VS Code.
- Local shell/git/file capabilities require PAT/local client context and explicit user permission.
- Web capability responses never include local-only actions.
- Tests include either backend API assertions, command-router assertions, PTY/screenshot evidence, or typed-stream parsing evidence, depending on the tag.
