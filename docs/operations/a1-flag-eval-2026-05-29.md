# A1 — worker-lever flag eval (2026-05-29)

> Originated from audit item **A1**. The old `docs/audit` source was removed after consolidation; this playbook is now the source of truth. Harness: [`scripts/a1-flag-eval.sh`](../../scripts/a1-flag-eval.sh).
> Raw: `scripts/v2-eval-results/a1-*/summary.csv`.

## What was measured

The five default-OFF worker levers landed across the engine-extraction + roadmap work, flipped **all on**
vs **all off**, on the same spec, per provider:

| Flag | Migration | Activates when |
| --- | --- | --- |
| `worker.tool-compactor.enabled` | V216 | a tool returns > 3 KB output |
| `worker.history-compaction.enabled` | V222 | worker history > ~60k tokens |
| `worker.build-tdd.enabled` | V217 | BUILD-mode task runs its own tests in-loop |
| `worker.provider-prompt-tuning.enabled` | V219 | provider-specific worker prompt fragment exists |
| `worker.cross-provider-fallback.enabled` | V220 | a task fails persistently on its primary provider |

Budget: **$10/provider** (user-set), per-run `userCostCap=$3`, BUILD mode, one **medium**-band spec per
cell. Run on `dev`-shaped local backend via the SUPER_ADMIN flag API. Flags reset to OFF after (verified).

## Results

| Provider | Baseline score | Flags-ON score | Baseline $ | Flags-ON $ | Δ score | Δ cost |
| --- | --- | --- | --- | --- | --- | --- |
| anthropic | 100 | 100 | 0.7351 | 0.6666 | 0 | **−9.3%** |
| openai | 91 | 97 | 0.9003 | 0.6336 | **+6** | **−29.6%** |
| gemini | 97 | 97 | 0.3587 | 0.3060 | 0 | **−14.8%** |

**Every provider got cheaper (−9% to −30%, mean ≈ −18%) with no quality regression; openai also gained +6
verifiedScore.** Directionally the levers are a clear win — the always-active ones (tool-compactor +
history-compaction) cut input-token spend, which is where the cost delta comes from (the medium spec
doesn't trip build-tdd / cross-provider-fallback, so this is mostly the compaction pair).

## Honest caveats

- **N = 1 per cell.** One spec, one run per (provider × condition). The cost reduction is consistent
  3/3 (strong directional signal); the openai **+6** is within plausible single-run variance and should
  not be read as a guaranteed quality lift.
- Single **medium** band only — LOW (cheap, less to compact) and HIGH (where build-tdd /
  cross-provider-fallback would actually fire) were out of the $10/provider budget and are unmeasured.
- verifiedScore is the deterministic additive score, not a human-graded correctness judgment.

## Recommendation

- **Safe to widen the eval, not yet to flip in prod.** Before defaulting any flag ON, run **N ≥ 3 per
  cell across LOW/MEDIUM/HIGH** so the per-band effect (esp. build-tdd on HIGH) is real, not anecdotal.
- The **tool-compactor + history-compaction** pair is the strongest candidate for first promotion given
  the consistent token-cost reduction with flat quality — but still gate on the wider matrix.
- Keep all five OFF by default until then (current state).
