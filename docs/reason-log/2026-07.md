### RL-2026-07-17-007 - Enforce one durable route and current credential at provider dispatch

### RL-2026-07-17-008 - Replace request-thread project exports with durable fenced jobs

- **Finding:** the project-export endpoint queried complete repository/contract/activity lists,
  built both NDJSON and the final gzip/tar in JVM heap, and returned the bytes on the request thread.
  It had no job identity, idempotency, workload limit, lease/restart recovery, cancellation, retry,
  expiry, object retention or download audit. The controller reflected raw exception messages and
  admitted `BILLING_ADMIN`, while the bundle itself documented missing content despite presenting
  as a complete project export.
- **Decision:** V289 introduces a tenant-bound export job and append-only audit ledger. A durable
  lease with monotonically increasing fencing token owns each attempt; expired work is reclaimed
  after restart, attempts/retry delay are bounded, and only the current token may publish a final
  object pointer. Daily quota, one active job per project and a bounded executor prevent fan-out.
  Cancellation and expiry are durable state transitions, not request-local flags; a cancellation
  whose worker dies is finalized after its lease expires rather than blocking the active-job slot.
- **Data contract:** schema-v2 archives stream through private spool files and carry explicit
  repository/contract/activity counts and truncation flags. Member identifiers, activity actor and
  target ids/payloads, credentials, provider keys, clone credentials, source and uploaded document
  bytes are excluded; remaining user text is secret-pattern redacted. `redaction.json` makes the
  omissions explicit, and the README no longer claims this metadata snapshot is a source backup.
- **Product/security:** only host `ORG_ADMIN` and `SUPER_ADMIN` may create/read/cancel/download;
  every handler still enforces project tenant access. Web queues, polls, cancels, streams/downloads,
  shows digest/expiry and exposes the immutable lifecycle history. Controller errors and durable
  error codes are fixed taxonomies; raw failures remain server-side.
- **Storage boundary:** private GCS is used only when the export-specific opt-in is enabled;
  local/single-VM deployments use a stable workspace object root. Multi-node local deployments
  require a shared mount or GCS. A GCS bucket lifecycle rule remains the final defence for the
  narrow crash window after an attempt upload but before its object key is committed.

### RL-2026-07-17-009 - Make Enterprise LLM usage reports bounded and uncertainty-aware

- **Finding:** the first V283 admin query used a rolling UTC-days window, returned every aggregate
  group, had no CSV, and allowed BILLING_ADMIN to inspect detailed physical attempts. Failed
  attempts whose provider returned no usage metadata carried the schema default `cost_usd=0`, so a
  report could misstate unknown provider spend as proven zero. Run, managed-AI and provider-invoice
  variance had no explicit status or tolerance.
- **Decision:** the canonical API now requires inclusive org-calendar `from`/`to` dates plus an IANA
  timezone and converts them to a half-open instant interval. It caps the window at 366 days, JSON
  page size and aggregate rows at 500, and spreadsheet-safe CSV details at 10,000 with explicit
  truncation headers. Detailed facts are own-org ORG_ADMIN/SUPER_ADMIN only. One combined roll-up
  carries user/provider/model/agent-role/feature/project/run/session/key-source/status, with run and
  session identity resolved only by exact tenant-scoped primary keys.
- **Truth contract:** provider-unreported failed-attempt cost is `null` with
  `UNKNOWN_PROVIDER_NOT_REPORTED`; totals are explicitly a known-cost lower bound. Reconciliation
  applies `max($0.000001, 0.5%)`, compares run recorded cost and exact managed-AI cost/tokens, and
  returns incomplete/indeterminate statuses when rows or cost facts are missing. Provider-invoice
  status remains unavailable because V283 has neither an invoice feed nor durable upstream request
  identifier; no invoice-reconciliation claim is made.
- **Operations:** the existing persistence-failure metric now has a routable Prometheus critical
  alert with owner, pager channel, runbook, test procedure and silence policy. It detects ledger loss
  but does not replay it; durable outbox/recovery and retention/partitioning remain open.

### RL-2026-07-17-010 - Govern project vectors and preserve retrieval without hidden OpenAI

- **Finding:** document ingestion, code indexing and both query-vector paths called OpenAI directly
  with `spring.ai.openai.api-key`. An OWN_KEYS DeepSeek project could therefore spend a platform
  OpenAI credential and send source/document content outside its selected-provider boundary.
  V286 could also keep reporting a code index READY after provider/key policy drift, while document
  READY had no provider/model provenance or lexical-only state.
- **Decision:** V290 pins the existing 1536-dimensional semantic corpus to governed OpenAI
  `text-embedding-3-small`. `EmbeddingPolicyResolver` first requires OpenAI to be the project's

  call then creates an idempotent project `EMBEDDING_JOB` V282 context and
  `LlmExecutionDispatchGuard` reloads the exact current USER/ORG/PLATFORM source. OWN_KEYS missing,

- **Fallback/data contract:** V290 persists document retrieval mode and vector provenance and makes
