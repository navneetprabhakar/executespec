### RL-2026-06-032 - OAuth callback state survives session-cookie loss
- **Change:** Add `CookieOAuth2AuthorizationRequestRepository` and wire Spring OAuth2 authorization requests through it. The repository stores each request in a 5-minute HttpOnly `SameSite=Lax` cookie keyed by a SHA-256 hash of OAuth `state`, signs the payload with `app.jwt.secret`, rejects tampering, and clears the cookie on callback.
- **Why:** Dev OAuth was failing with `OAuth2AuthenticationException: [authorization_request_not_found]` on the provider callback even though `/api/auth/oauth2/authorize/{provider}` issued correct Google/GitHub redirects. A controlled callback with a fresh single `ESDEVSESSION` reached token exchange, proving provider config was not the issue; the real browser path was losing or presenting the wrong session state. Persisting the authorization request by `state` makes login resilient to missing/stale/duplicate session cookies and parallel OAuth attempts.
- **Tradeoff:** The callback now carries one short-lived signed cookie per in-flight OAuth state. The payload is protected against client tampering but still bounded by browser cookie limits; current Google/GitHub request objects are small enough and covered by unit tests.
- **Code:** `src/main/java/com/navneet/executespec/auth/oauth/CookieOAuth2AuthorizationRequestRepository.java`, `src/main/java/com/navneet/executespec/auth/security/SecurityConfig.java`, `src/test/java/com/navneet/executespec/auth/oauth/CookieOAuth2AuthorizationRequestRepositoryTest.java`
