# 2026-06 Reason Log

Newest entries first.

### RL-2026-06-028 - Model matrix exposes display labels to the UI
- **Change:** `GET /api/org/me/model-matrix` now includes `modelLabels` keyed by model id, populated from `ModelRegistry.displayLabelFor`.
- **Why:** The model selector should not render raw provider ids when YAML already owns display labels. Keeping labels server-derived prevents frontend drift when model ids change.
- **Tradeoff:** Adds a small map to the org matrix DTO; legacy clients that ignore unknown fields remain compatible.
- **Code:** `src/main/java/com/navneet/executespec/auth/controller/OrgController.java#modelMatrix`

### RL-2026-06-027 - Console becomes the protected web shell
- **Change:** Mount `ConsoleShell` for all protected routes, remove the `localStorage es:console` opt-in path and `IdeWorkspace`, add `/decisions`, keep the existing `ide/` components as route-level surfaces, and lazy-load heavy admin/discovery/billing/org/legal chunks.
- **Why:** The browser app is a control plane, not the editing environment. Keeping a VS Code-style shell in the web app duplicated the VS Code extension metaphor and made mobile monitoring harder. Console gives the product a stable operator shell for runs, projects, decisions, billing, model settings, and benchmark monitoring.
- **Tradeoff:** This is a large visual/navigation change and must be visually QA'd before merge. The code-level route components remain mostly intact to keep the behavior risk bounded.
- **Code:** `frontend/src/App.tsx`, `frontend/src/console/ConsoleShell.tsx`, `frontend/src/console/ConsoleHome.tsx`, `frontend/src/console/ConsoleDecisions.tsx`, `frontend/src/stores/useUiStore.ts`

### RL-2026-06-026 - Verified score trust caps and evidence ledger
- **Change:** Keep the additive `verifiedScore` formula, then cap the headline when verification signals show review/build/test risk; expose `verificationLedger[]` on validation reports; extend the SUPER_ADMIN backfill endpoint with `{runId, limit, dryRun}` and recompute both `verifiedScore` and `rubricScore`.
- **Why:** A high internal score without visible evidence reads as self-scored proof. The score still needs to summarize routing quality, but the product surface must show which claims are deterministic, which are LLM assessments, and which are only the internal formula.
- **Tradeoff:** Strong partial work can no longer headline above the cap even if the weighted formula would be higher. This is intentional: unresolved review, build, or test signals should force operator/customer review before external use.
- **Code:** `src/main/java/com/navneet/executespec/report/ValidationReportService.java#computeVerifiedScore`, `src/main/java/com/navneet/executespec/report/ValidationReportService.java#buildVerificationLedger`, `src/main/java/com/navneet/executespec/report/VerifiedScoreBackfillService.java#backfill`
