### RL-2026-06-197 - Agent web fetch uses pinned bounded transport

- **Tag:** `SECURITY-AUDIT`, `TERM-AUDIT-SERVER-CONTRACT`, `WEB-AGENT-AUDIT`
- **Change:** Replaced chat `web_fetch`'s whole-body `HttpClient.BodyHandlers.ofString` transport with a pinned-address, bounded-byte HTTP transport. The tool now resolves and validates the host once, connects to the selected `InetAddress`, rejects non-default ports, does not follow redirects, rejects compressed/non-text/oversized responses before returning content, caps response headers/body before decoding, and keeps fetched data `untrusted`-flagged.
- **Why:** The read-only web surface is required for the real CLI/web agent experience, but the previous implementation still had a DNS rebinding TOCTOU gap and loaded the complete response body before the 8 KB output cap.
- **Behavior:** Public HTTP/HTTPS text fetches continue to work. Local/private/metadata targets, suspicious egress query keys, non-default ports, redirects, compressed responses, large `Content-Length`, binary content types, and bodies beyond the byte cap fail closed.
- **Code:** `src/main/java/com/navneet/executespec/specchat/WebSearchChatTools.java`, `src/test/java/com/navneet/executespec/specchat/WebSearchChatToolsTest.java`, `src/main/java/com/navneet/executespec/report/ValidationReportEvidenceEvent.java`, `src/main/java/com/navneet/executespec/agentsession/CLAUDE.md`.
