Methodology

What "blind" means here.

  • Issue-only spec. The pipeline sees the task description — the same natural-language spec a customer would submit. It never sees the benchmark's test suite, the expected patch, or any oracle hint.
  • Hidden tests, applied externally at scoring. The benchmark harness scores the produced change against tests the pipeline never saw, after the run is over. The agent can't train to the test.
  • The production pipeline, unmodified. Runs execute the same planner / worker / reviewer code path, the same tools, and the same prompts that customer runs use — no task-specific prompts, no benchmark-only branches in the agent.
  • Derived numbers are computed, not typed. Resolved % and cost-per-resolved are calculated by this page from the raw counts in the published data file, so a number can't drift from its source.
Honesty policy

What we don't publish.

  • Oracle-mode results are discarded. If a run ever saw the benchmark's tests in its prompt (test-in-prompt), its numbers are thrown away — they measure prompt leakage, not capability. We have discarded our own earlier oracle-mode SWE-bench numbers under this rule.
  • Suites in re-measurement are listed as pending, not estimated. A name-only row, no projected numbers.
  • No naked percentages. A result is only publishable with its mode, slice, model, and run date attached — "12/20 on the first-20 slice" is a claim we can defend; "60%" alone is not.
