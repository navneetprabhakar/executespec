How it works

From spec to shipping, in four stages.

Every run flows through the same pipeline. Each stage has its own quality gate. You see progress live.

STAGE 01

Spec

Write what you want — endpoints, validation, acceptance criteria. Or paste a JIRA ticket. Or import a Figma URL.

STAGE 02

Plan

The planner agent decomposes the spec into a task DAG with an explicit requirement graph. In Production Mode you review before compute burns.

STAGE 03

Execute

Worker agents build each task. Every change goes through syntax, type, lint, and test gates. Failed gates retry with the error injected back in.

STAGE 04

Verify & Ship

Reviewer passes (general + wiring) auto-fix issues. Final build smoke test. You get a verified score 0–100, a live preview, and a GitHub PR.

Why our code actually compiles.

Every task passes through a deterministic validation chain before it lands. Here's a real run.

user@executespec:~$ tail -f /run/c2f83bfa/pipeline.log
[INFO] PLAN Planner decomposing spec into 3 tasks...
[OK] Plan approved (production mode, 3 tasks, est. $0.08)

→ Task 1/3 Add /api/health endpoint with uptime
↳ Worker (sonnet-4.6) writing src/routes/health.ts...
✔ syntax: passed · type: passed · lint: passed
✘ test(fails): Expected uptime > 0, got undefined
[RETRY] Injecting error context, retrying...
↳ Worker applying fix (process.uptime())...
✔ test(passes): 4/4 · build: passed

→ Task 2/3 Unit tests for health endpoint
✔ all gates passed on first try

→ Task 3/3 README + OpenAPI entry
✔ all gates passed

REVIEW Reviewer (general + wiring) inspecting codebase...
[OK] Reviewer verdict: CLEAN (0 critical, 0 major)
[OK] Final build: SUCCESS
[DONE] Verified 92/100 · preview: preview-c2f83bfa.run.app · PR #58 opened

Deterministic gates, not hope.

  • ✓ Syntax & type. Run tsc, mypy, javac on the exact modified files.
  • ✓ Strict lint. React hooks violations are fatal. No spaghetti leaks in.
  • ✓ Auto-retry. Failed gate? The compiler error is injected back into the worker's context.
  • ✓ Auto-fix review. Reviewer passes (general + wiring) catch critical issues and patch them with a stronger model.
  • ✓ Verified score. 40 (build) + 20 (tests) + up to 20 (reviewer) + 20 (base) − 5×unfixed-critical. No LLM in the math.

FAQ

Questions we hear a lot.

What exactly is a "run"?
A run is a single end-to-end execution of the ExecuteSpec pipeline triggered by submitting a spec: planning → task execution with validation gates → reviewer passes → validation report. Runs count regardless of outcome; retries within a run don't count as additional runs.
How is the "verified score" calculated — isn't this just another AI opinion?
It's deterministic. The formula is: 40 (final build passed) + 20 (tests passed %) + up to 20 (reviewer verdict: CLEAN = 20, FIXED = 15, UNRESOLVED = 5) + base 20 − 5 per unfixed critical issue. Clamped to 0–100. No LLM in the calculation. We still show an LLM "estimate" score for context, but the verified score is the one you can trust.
Does "unlimited" on Max actually mean unlimited?
Max has a fair-use ceiling around 500 runs / month and 3 concurrent runs. Above that we reach out about Enterprise. Automated/scripted submission and load testing aren't fair use. For individual engineers shipping at normal velocity you'll never hit it.
How does BYOK save me money?
On Max you pay $29/mo to us for the workflow (planner, worker, reviewer, gates, preview, project workspace, scoring). Your API tokens are billed directly by Anthropic / OpenAI / Google — we don't mark them up. At typical usage ($0.10–$0.80 per run) this is 30–60% cheaper than a comparable managed-keys plan at the same run volume.
Will this work on my codebase?
Supported out of the box: Java, TypeScript, React, React Native + Expo, Python, Go, Rust, HTML/CSS. ExecuteSpec can clone an existing repo (MAX+) or start from scratch. For enterprise stacks with custom build systems we offer an onboarding call.
How does this compare to Cursor / Windsurf / Claude Code / Lovable / Bolt?
Cursor / Windsurf / Claude Code are agentic IDEs — powerful but require constant human steering. Lovable / Bolt / v0 are great for zero-to-one prototypes but wobble on complex business logic. ExecuteSpec is the spec-driven alternative: you write a spec once, the pipeline runs end-to-end with deterministic gates, and you get a verified score before you merge. We complement, not replace, agentic IDEs.
Is my data used for model training?
No. All three providers (Anthropic, OpenAI, Google) are contracted to not train on customer data. We don't store your code beyond retention limits, and on Enterprise retention is unlimited (you control deletion). Signed DPA with Standard Contractual Clauses available for EU customers.
