# be-core-agents — raw findings

Reviewed as-is on branch `benchmark` incl. uncommitted changes (LlmRouter Fireworks additions, new `router/FireworksModelMapper.java`). Every `.java` file in `agent/` (43 files, ~8,987 LOC incl. `agent/model/`), `context/` (7 files, 932 LOC), `composer/` (2 files, 291 LOC) read in full; 21 matching test files (4,668 LOC) skimmed/read. All conclusions from code/config only — no docs consulted; CLAUDE.md content auto-injected by tooling was disregarded.

## 1. Inventory

### `agent/` (~9K LOC) — LLM routing + planning agents + BYOK key plumbing + plan data types
- **Routing core:** `LlmRouter.java` (668) — V2 native-tool dispatcher: provider switch (anthropic/openai/gemini/openrouter/deepseek/fireworks), bounded same-provider transient retry (4 attempts, 2s/4s/8s backoff), flag-gated multi-provider failover (`router.failover.enabled`) walking `ModelRegistry.fallbackChainFor`, per-customer-key Anthropic model cache (Caffeine, SHA-256 keyed), Anthropic prompt-cache options, forced-tool-choice salvage delegation. `OpenAiNativeToolClient.java` (358) — hand-rolled OpenAI-wire client (also serves openrouter/deepseek/fireworks via per-call baseUrl); DeepSeek `reasoning_content` round-trip; cached-token surfacing. `GeminiNativeToolClient.java` (719) — hand-rolled Gemini REST client; schema sanitization (`additionalProperties` strip), thought-signature cache, 429 retry, flag-gated explicit context caching (`gemini.explicit-cache.enabled`). `AnthropicForcedToolClient.java` (189) — single-turn `ToolChoiceAny` salvage bypass. `FallbackLlmRouter.java` (1,036) — deprecated V1 router with provider chain walk, circuit breaker, pin store, rate-limit retry ladders (15/30/60/120s); 19 live calling classes (enumerated in §3).
- **Planning:** `SmartClassifierAgent.java` (602) — heuristic + LIGHTWEIGHT LLM verifier + Redis cache → `PlanStrategy`. `OutlinePlannerAgent.java` (529) — FULL_PLAN/SKELETON_ONLY via `submitOutline` tool call, wall-clock timeout wrapper, SINGLE_SHOT synthesis. `TaskExpanderAgent.java` (328) — per-skeleton body fill via `submitTaskDetail`. `CoherencePlannerAgent.java` (442) — `patchPlan` with 5 patch kinds. `PlannerOutputUtils.java` (412) — parse/validate/salvage statics. `PatchAgent.java` (218) — PATCH-mode delegation to `engine/WorkerAgent` with per-provider iter caps. `PlanStrategyCircuitBreaker.java` (142) — Redis per-strategy breaker with degrade ladder. `SpecClassifier.java` (136) — *V1* 3-value classifier, still live (`RunOrchestrator:1090`) feeding `Classification` → `maxTasks` cap.
- **Keys/BYOK:** `ApiKeyResolver.java` (179) user→org→system resolution; `RunKeyContextStore.java` (121) + `RunKeyContext.java` (84) — V2 per-run key cache consumed by `LlmRouter`; `RunKeyStore.java` (129) + `ResolvedKeys.java` (59) — V1 two-layer store consumed by `FallbackLlmRouter`/`AvailableProviderResolver` **but written by nobody** (see Findings).
- **Support:** `PromptAssembler.java` (139) include-resolution + `{{VAR}}` substitution; `PromptResourceVerifier.java` (79) boot-time prompt existence gate; `PromptAudit.java`/`PromptHashAuditRepository.java` (dead — §3); `CostEstimator.java` (385) DB-priced estimates (mostly dead) + live `computeCostForRun`; `TokenBudgetMonitor.java` (234)/`TokenBudgetPolicy.java` (40) (mostly dead); `RunTitleSummarizer.java` (93); `ConversationAgent.java` (844) — only `generateSuggestionPlan` is live; data types `Plan`/`PlannedTask`/`PlannerRequest`/`LlmRequest`/`Classification`/`ClassificationResult`/`PlanStrategy`/`RequirementSpec`; `agent/model/` V1 DTOs (`TaskPlan`, `TaskDefinition`, `TaskReview*`, `ReviewIssue`, `WorkerReport`, `IterationEstimate`) used by `StateStore`, `ConversationAgent`, `PreviewAgent`.
- Connects to: `router/` (ModelResolver/ModelRegistry/mappers), `tool/` (ToolRegistry, ExecutionContext), `cost/RunCostTracker`, `sse/SseBroadcaster`, `engine/WorkerAgent` (PatchAgent), `integration/RunOrchestrator` + `RunPlanningCoordinator` (planning entry), `harness/SequentialExecutor` (ContextStore consumer).

- `ContextStore.java` (294) — Redis persistence of worker message history (`v2:agent-ctx:{runId}:{taskId}`, 24h TTL), hand-rolled discriminated-union serialization; consumed by `engine/WorkerAgent` (save/delete) + `harness/SequentialExecutor` (load/deleteAll). `SavedContext.java` (27), `package-info.java` (37).

## 2. Findings

Real bugs first.

- **[BUG] Classifier LLM cost is never attributed to the run — `pipeline_run.classifier_{input,output,cost}` are always 0 when the verifier fires.** `SmartClassifierAgent.java:357-361` builds `ExecutionContext("classify-" + projectId, "__planner_classifier__", tmpdir)`, so `LlmRouter` → `RunCostTracker.record(...)` books the call under the synthetic runId `"classify-<projectId>"` (and emits SSE tokenUsage to that nonexistent run). `RunPlanningCoordinator.java:110-118` then diffs `costTracker.snapshot(runId)` (the *real* runId) before/after — always 0/0/$0. The comment at `SmartClassifierAgent.java:442-445` ("the orchestrator diffs the run accumulator … to attribute the phase cost") describes a mechanism the runId mismatch makes impossible. Classifier spend is silently orphaned.
- **[BUG] `RunKeyStore` is written by nobody — the legacy router's entire BYOK path is inert.** `RunKeyStore.put()`/`.remove()` have zero callers repo-wide (only `.get()` is called: `FallbackLlmRouter.java:189,738`, `AvailableProviderResolver.java:55`); the lifecycle in the class javadoc (`RunKeyStore.java:30-35`, "RunOrchestrator.executeRunAsync → runKeyStore.put") is false — the orchestrator populates only the V2 `RunKeyContextStore` (`RunOrchestrator.java:856`). Since `get()` miss returns `ResolvedKeys.SYSTEM_ONLY` (mode "SYSTEM"), every call through `FallbackLlmRouter` — all 19 caller classes incl. ValidationReportGenerator, testgen agents, ConversationAgent, ContextAgent, codeintel generators — runs on **platform keys**, and the OWN_KEYS hard-fail branches (`FallbackLlmRouter.java:746-748, 815-817, 832-834, 849-851`) can never fire. OWN_KEYS (pure-BYOK) orgs get these LLM calls billed to the platform, contradicting the enforcement the same orgs get on the V2 path.
- **[BUG] FREE-tier model lock on the legacy router never fires.** `FallbackLlmRouter.java:151-155` forces `modelRegistry.freeTierProvider()/freeTierModel()` when `getRunUserTier(runId)=="FREE"` — but `setRunUserTier` has zero callers repo-wide, so the tier cache is always empty and the lock is dead. Same for `getRunCallCount`/`clearRunCallCounter` (zero callers → run counters/pins are never cleaned at run end through this path).
- **[BUG] `prReviewComments` is silently discarded by the V2 planner.** `RunOrchestrator.java:1231` populates `PlannerRequest.prReviewComments`, the prompt has the marker (`prompts/outline-planner.md:143`), but `OutlinePlannerAgent.planOnce` (`OutlinePlannerAgent.java:343`) does `.replace("{{PR_REVIEW_COMMENTS}}", "")` unconditionally and never reads `req.prReviewComments()`. The "plan from PR review feedback" feature is wired end-to-end except the last inch. (`{{MOBILE_PREFERENCE_BLOCK}}` at line 342 is likewise always blanked — vestigial marker.)
- **[BUG] Explicit `toolChoice="required"` is silently dropped for native DeepSeek.** `OpenAiNativeToolClient.buildRequestBody` (`OpenAiNativeToolClient.java:187-190`) suppresses `tool_choice` entirely whenever `baseUrl.contains("deepseek")` — including when the caller explicitly set `"required"`. The V224 forced-tool-choice salvage (`worker.salvage-force-tool-choice.enabled`), whose whole purpose was rescuing DeepSeek zero-edit runs, therefore cannot work on the native DeepSeek route. The blanket suppression conflates "thinking-mode models reject tool_choice" with the active non-thinking `deepseek-v4-flash-native`. Detection by URL substring is also brittle (a proxy URL without "deepseek" re-enables it and 400s thinking models).
- **[BUG] `FallbackLlmRouter`'s documented guardrail modes are unimplemented.** The class javadoc (`FallbackLlmRouter.java:55-60`) specifies four TASK_BOUNDARY rules and `MidTaskProviderFailureException`; the code only distinguishes `NO_FALLBACK` (`maxAttempts` at line 193). `TASK_BOUNDARY` behaves identically to `IMMEDIATE`; `iteration`/`justCompacted` params are decorative; `MidTaskProviderFailureException` (lines 1031-1035) is never thrown anywhere.
- **[BUG-minor] Source-corrupted prompt text:** `ConversationAgent.java:552` contains two U+FFFD replacement characters (`ef bf bd ef bf bd` verified via hexdump) in the "DESIGN GUIDANCE" divider of `buildSystemPrompt` — mojibake checked into the repo (in code that is currently dead, see §3, but it documents a broken edit pipeline).
- **[BUG-minor] `SpecClassifier.DOMAIN_KEYWORDS` lists `"checkout"` twice** (`SpecClassifier.java:38` and `:70`), so `distinctDomains` double-counts any spec containing "checkout", biasing toward MULTI_TASK. A `Set.of` would have caught this at class-load.
- **[BUG-minor] Planner wall-timeout neither cancels nor interrupts.** `OutlinePlannerAgent.planOnce` (`OutlinePlannerAgent.java:378-402`) runs the blocking LLM call via `CompletableFuture.supplyAsync` on the common ForkJoinPool; on `TimeoutException` the task keeps running (and billing) — `fut.cancel` is never called, and the comment ("`.get(timeout)` interrupts") is wrong. Blocking I/O on the commonPool can also starve unrelated parallel work.
- **[RISK] Gemini API key in URL query string.** `GeminiNativeToolClient.java:188` (`?key=" + apiKey`) and `:649` (cachedContents mint). A `ResourceAccessException` from Spring's RestClient embeds the full URI in its message — which this codebase logs and even message-sniffs — so a connection failure can leak the key into logs. The `x-goog-api-key` header is never used.
- **[RISK] BYOK has no deepseek/fireworks lane but router comments claim it does.** `RunKeyContext.keyFor` (`RunKeyContext.java:49-55`) returns null for `"deepseek"`/`"fireworks"`; `ResolvedKeys`/`ApiKeyResolver` have no fields for them. `LlmRouter.java:141,150` comments say "Org BYOK keys via RunKeyContext.keyFor(\"deepseek\"/\"fireworks\")" — false today; those providers always use the platform `spring.ai.*.api-key` (which `callDeepSeek`/`callFireworks` at least fail loudly on when blank).
- **[RISK] Resume breaks thinking-model round-trip state.** `ContextStore.serializeMessage` (`ContextStore.java:196-208`) drops `AssistantMessage` properties — losing DeepSeek `reasoning_content` (`OpenAiNativeToolClient.REASONING_CONTENT_META_KEY`, required to be echoed back per `OpenAiNativeToolClient.java:225-235`); Gemini thought-signatures live only in an in-memory Caffeine cache (`GeminiNativeToolClient.java:123-124`). A task resumed from a Redis snapshot (different JVM or post-restart) will 400/degrade on those providers.
- **[RISK] `FallbackLlmRouter` silently drops tool callbacks on the Gemini branch.** `callWithModelOptions` Gemini case (`FallbackLlmRouter.java:777-781`) builds `GoogleGenAiChatOptions` without `toolCallbacks`/`internalToolExecutionEnabled`, unlike the Anthropic branch (771-774) and the OpenAI native path. Any tool-bearing prompt that fails over to Gemini loses its tools without error.
- **[RISK] error classification by message substring.** `LlmRouter.isTransientError` (`LlmRouter.java:361-396`) and `FallbackLlmRouter.isTransientServerError`/`isFatalClientError` (`FallbackLlmRouter.java:957-996`) match `"503"`, `"400"`, `"connection"`, `"timeout"` etc. anywhere in the message — `"maximum context length is 4003 tokens"` contains "400"→fatal (accidentally right), `"processed 1500 items"` contains "500"→transient retry. Typed checks exist only for a few Spring exceptions; the three hand-rolled clients throw heterogeneous types so misclassification is reachable.
- **[PERF] New `HttpClient` + `RestClient` per LLM call.** `OpenAiNativeToolClient.call` (`OpenAiNativeToolClient.java:112-116`) and `GeminiNativeToolClient.call` (`GeminiNativeToolClient.java:157-164`) construct a fresh JDK HttpClient (own connection pool + selector threads) on every call on the hottest path in the system — defeats keep-alive/HTTP2 reuse and churns sockets under multi-iteration worker loops.
- **[PERF] `redis.keys()` scan in `ContextStore.deleteAll`** (`ContextStore.java:153`) — `KEYS` is O(keyspace) and blocks Redis; called at every run end. Should be `SCAN` or an index set (the package-info at `context/package-info.java:17-18` even documents an index key that was never implemented).
- **[PERF] Legacy-router retry ladders block request threads for minutes.** `handleRetryAfterSleep` sleeps 15+30+60+120s per provider (`FallbackLlmRouter.java:580-680`), and the chain walk can invoke it per provider — worst case >7 min of `Thread.sleep` inside a single call, with no caller-configurable budget.
- **[INCONSISTENT] Two classifier systems run in the same pipeline.** V1 `SpecClassifier`→`Classification` (3-value; live at `RunOrchestrator.java:1090`) still drives the `maxTasks` truncation in `PlannerOutputUtils.parsePlanFromArgs` (`PlannerOutputUtils.java:76-82`, MEDIUM caps plans at 4 tasks) while V2 `SmartClassifierAgent`→`PlanStrategy` (5-value) drives mode selection. Two heuristics, two enums, one run — divergent verdicts are reconciled nowhere.
- **[INCONSISTENT] Five prompt-handling mechanisms in one package:** `PromptAssembler` (SmartClassifier), raw `ClassPathResource` + chained `.replace()` (OutlinePlanner `OutlinePlannerAgent.java:503-509`, TaskExpander `:258-264`, CoherencePlanner `:325-331`), `@Value Resource` + `@PostConstruct` (PatchAgent `:195-209`, ContextAgent `:48`), inline Java text blocks (ConversationAgent `generateSuggestionPlan` `:226-264`, RunTitleSummarizer `:32-42`), and a synthetic SystemMessage string (SmartClassifier `:352-354`). Variable substitution via `.replace()` also means a `{{VAR}}` occurring in user spec text gets substituted (prompt-injection-adjacent) and missing markers fail silently.
- **[INCONSISTENT] Hardcoded `OPENAI` default provider in five fallbacks** — `PlannerOutputUtils.resolveProviderForTitle:401,404,409`, `TaskExpanderAgent.resolveProvider:312,316`, `CoherencePlannerAgent.resolveProvider:386,390`, `SmartClassifierAgent:298`, `RunTitleSummarizer:56` — while `CostEstimator.estimate` defaults to `ANTHROPIC` (`CostEstimator.java:89`) and `agent.roles.*` config says anthropic. A null-provider run silently plans on a different vendor than it executes on.
- **[INCONSISTENT] Same `LlmRequest` ⇒ different tool-choice semantics per provider.** `toolsOverride` non-empty forces Gemini into `ANY` mode (`LlmRouter.callGemini:542` + `GeminiNativeToolClient.buildRequestBody:403-413` — the model *cannot* emit plain text), OpenAI gets `tool_choice:"auto"`, Anthropic auto. `LlmRequest` javadoc (`LlmRequest.java:35-40`) is additionally stale: it claims Anthropic ignores `toolChoice`, but `callAnthropic` honors `"required"` via `AnthropicForcedToolClient` (`LlmRouter.java:426-432`).
- **[INCONSISTENT] Fireworks is half-wired (the uncommitted change).** Dispatch case + `LlmProvider.FIREWORKS` + `spring.ai.fireworks.*` exist, but `model-matrix.providers` has no `fireworks:` tier row and `model-matrix.models` contains no `provider: fireworks` entries — the `FireworksModelMapper` ids (`qwen3-coder-fw`, `deepseek-v3-fw`, `kimi-k2-fw`, `glm-4p6-fw`, `deepseek-v3p1-fw`) are unregistered, so they have no pricing (cost tracking will miss), no context-limit, and can't pass org-override validation. Reachable only via a raw provider/model pin.
- **[INCONSISTENT] `ConversationAgent.chat` pins "anthropic" + `lightweightModelFor("anthropic")` claiming "Haiku" (`ConversationAgent.java:124-128`)** — the matrix now maps `anthropic.lightweight: claude-sonnet-4-6` (`application.yml:89`), so the comment's cost assumption is 3× off. Moot only because the method is dead (§3). Same all-flagship drift applies to anything reasoning "LIGHTWEIGHT = cheap".
- **[INCONSISTENT] `ContextAgent.runAsync` spawns a bare virtual thread** (`ContextAgent.java:70-73`) without the `ContextSnapshotFactory` wrapping used by sibling async dispatches (`TerminalBenchRunService:255`, `IntegrationOutboundListener:70`, `TestGenOrchestrator:117`) — traceId/MDC and tenant context are lost for all Context-Agent logs/LLM calls.
- **[INCONSISTENT] `RunKeyContextStore` mislabels org keys as USER.** `RunKeyContextStore.java:58-66` stamps any non-null anthropic/openai/gemini key as `Source.USER` even when it came from the org level (acknowledged in the comment at 67-75) — `pipeline_run.key_source` and the key-source metric are wrong for org-keyed runs.
- **[SMELL] `TaskExpanderAgent` schema advertises `smokeTestStrategy` override (`TaskExpanderAgent.java:234`) that `mergeExpansion` (165-212) never reads** — the LLM can "set" it; it's discarded.
- **[SMELL] `SmartClassifierAgent` keyword matching is substring-based** (`SmartClassifierAgent.java:229-232`): `"auth"` matches "author", `"search"` matches "research", `"tenant"` matches "lieutenant" — short specs get needlessly LLM-verified (cost) or escalated.

- **[DUPLICATION] `resolveProvider` triplicated:** `TaskExpanderAgent.java:311-318` ≡ `CoherencePlannerAgent.java:385-392` ≡ (modulo the redundant pre-check) `PlannerOutputUtils.resolveProviderForTitle:400-411` (whose inner try/catch is unreachable after the `noneMatch` guard).

- **[LAYERING] `ConversationAgent` (agent layer) reaches into `deployment/` (`PreviewService`, `WorkspaceFileService`), `report/` repository, and `state/` directly** — it behaves as a service/controller-tier aggregator living in `agent/`.
- **[PERF] `ContextAgentScanner.detectNewPackages/detectNewFiles`** (`ContextAgentScanner.java:62-67, 74-80`) leak `Files.walk` streams (no try-with-resources → file-handle leak on large trees) and use `currentDoc.contains(name)` per class — O(files × doc-size) and false negatives on substrings; also hardcodes `src/main/java` (Java-only assumption for a multi-language platform).

## 4. Model/LLM touchpoints

## 5. Libraries

- **Spring AI 1.1.x** — only the Anthropic path uses it end-to-end (`AnthropicChatModel`/`AnthropicApi`); OpenAI + Gemini are hand-rolled REST clients citing Spring AI 1.1.4 bugs (`extra_body`; `Optional.get` in GoogleGenAi multi-turn parsing). Result: three different HTTP stacks (Spring AI internals; `RestClient` + `JdkClientHttpRequestFactory` built per call; low-level `AnthropicApi`) with three different timeout/retry behaviors. Worth re-validating whether 1.1.6 still has both bugs — the wrappers' raison d'être is recorded only as comments about 1.1.4.
- **Caffeine** — used appropriately and consistently for bounded TTL caches (key stores, thought signatures, per-key models, breakers).
- **Jackson** — fine; `SlotValidator` news up a static private `ObjectMapper` rather than Spring's (acceptable for a static utility); `PlannerOutputUtils` takes the mapper per call (good).
- **JGit** — `ContextAgentScanner.buildGitDiffSummary` uses `Git.diff()` with no `setCached`/tree boundaries: it diffs worktree vs index only; whether that matches "files changed in run" depends on commit timing — fragile.
- **Micrometer/Observation** — `FallbackLlmRouter` is heavily Observation-instrumented while `LlmRouter` uses the bespoke `Metrics` facade; the two routers expose disjoint metric vocabularies (`executespec.llm.call` vs `recordLlmLatency`) — split-brain observability for the same concern.
- **Reinvented in-house:** OpenAI/Gemini wire clients (justified, but accreting per-provider hacks — DeepSeek reasoning echo, baseUrl sniffing); `SpecComposer` is a micro-Mustache (fine, small); `PlannerOutputUtils.salvagePlanFromText` builds JSON by string concatenation without escaping keys (salvage-only, acceptable); 4 SHA-256 helpers and 6 truncate helpers (use one util); hand-rolled message serialization in `ContextStore` (justified by Spring AI Message non-serializability, but now silently drops metadata/properties — see §2 RISK).
