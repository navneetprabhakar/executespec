# `agent/` — LLM agents + routing

> Last reviewed: 2026-05-12 (1.0.0-M1).

All LLM-calling agents + the routing infrastructure for the V2 pipeline.

## Key files

| File | Purpose |
|------|---------|
| `LlmRouter.java` | Canonical native-tool-calling dispatcher. Routes per provider (Anthropic via Spring AI, OpenAI via `OpenAiNativeToolClient`, Gemini via `GeminiNativeToolClient`). Every call flows through `RunCostTracker` (cache-aware pricing from `application.yml model-matrix.model-pricing`). **Bounded same-provider retry** (RL-2026-05-029): up to 4 attempts, exponential backoff (2s/4s/8s), only on transient errors (5xx / connection reset / I/O timeout / 429 via `isTransientError`); permanent 4xx fail fast. Retries the SAME provider (no failover) to keep per-provider numbers honest + survive transient upstream blips. **`LlmRequest.toolChoice`** (RL-2026-05-059): nullable OpenAI-wire `tool_choice` override (`"auto"`/`"required"`/`"none"`) passed through to the OpenAI-wire clients (`callOpenAi`/`callOpenRouter`/`callDeepSeek`); Anthropic + Gemini ignore it. Used by the WorkerAgent forced-tool-choice salvage. |
| `FallbackLlmRouter.java` | **DEPRECATED (RL-2026-05-041) — no new callers; migrate to `LlmRouter`.** Legacy V1 router; still used by ~14 non-tool-calling agents (`AccuracyAssessmentService`, `ConversationAgent`, `testgen/*`). Multi-provider fallback via YAML `failover-order`. Emits `RUN_PROVIDER_SWITCHED` SSE on fallback. `FallbackMode.NO_FALLBACK` opts out (used when `-Dexecutespec.strict-provider=true`). The divergent retry/failover vs. `LlmRouter` (audit risk #10) is a transitional fork pending migration. |
| `OpenAiNativeToolClient.java` | OpenAI native-tool client — bypasses Spring AI 1.1.4's `extra_body` bug; auto-cache validated at 43%. |
| `GeminiNativeToolClient.java` | Gemini native-tool client — schema sanitization + thought-signature round-trip; implicit-cache prefix preserved. **Explicit context caching** (RL-2026-05-059, flag `gemini.explicit-cache.enabled`, V225, default OFF): mints a `/v1beta/cachedContents` resource for the stable system+tools+toolConfig prefix, references it by name per call + OMITS those from the request body (Gemini 400s if `cachedContent` + system/tools/tool_config are both set) → prefix billed at the cache rate; keyed by SHA-256(model+systemText+toolsJson), fail-safe inline fallback on any mint/stale-cache 4xx. Records `cache_read_input_tokens` on every call. |
| `SmartClassifierAgent.java` | (LIGHTWEIGHT) Picks `PlanStrategy ∈ {SINGLE_SHOT, SMALL, MEDIUM, LARGE, LEGACY}`. Heuristic fast path (≤150-char tiny specs, no multi-feature keywords) returns at 0ms / $0; LLM verifier hits Haiku/Flash with the heuristic verdict as a hint. Redis cache 1h TTL keyed by `SHA-256(spec + sortedRepos + projectId)`. Always falls back to heuristic on parse / enum / timeout error. |
| `OutlinePlannerAgent.java` | (PLANNING) Two modes — `FULL_PLAN` (32k cap, single `submitPlan` tool call) for SMALL/MEDIUM; `SKELETON_ONLY` (8k cap, id/title/complexity/repos/dependsOn/type only) for LARGE/LEGACY. SINGLE_SHOT bypasses the LLM via `synthesizeSingleShot`. Both prompts (`outline-planner.md` + `outline-planner-skeleton.md`) bias toward **single-responsibility / fewest-cohesive-tasks** (NOT single-file-per-task) to curb over-decomposition (RL-2026-05-011). |
| `TaskExpanderAgent.java` | (WORKHORSE) Per-LEAF parallel expander. `submitTaskDetail` tool fills description / touchesFiles / hardConstraints / meetsRequirements. Dispatched via `CompletableFuture.allOf` on the 4-thread pipeline pool, 20-min wall timeout (LARGE/LEGACY). Per-task failures fall back to title-derived LEAFs. |
| `CoherencePlannerAgent.java` | (LIGHTWEIGHT) `patchPlan` tool with 5 patch kinds (ADD_MEETS_REQUIREMENT / ADD_DEPENDS_ON / REMOVE_DEPENDS_ON / FIX_HARD_CONSTRAINT_CONFLICT / MOVE_FILE_TO_REPO_SUBDIR). Empty patches array = clean plan. Non-fatal on per-patch failure. |
| `WorkerAgent.java` | **→ relocated to `engine/WorkerAgent.java` (Phase 4, RL-2026-05-052).** Still WORKHORSE-tier (mapping below unchanged); see [`engine/CLAUDE.md`](../engine/CLAUDE.md) for the worker loop. (per-task tier — LOW=LIGHTWEIGHT / MEDIUM=WORKHORSE / HIGH=PLANNING) Sequential multi-turn loop. Native tool calling end-to-end via `LlmRouter`. `CompleteTaskTool` terminates. **One progress signal** (RL-2026-05-005): `itersSinceProgress` → one UserMessage nudge at `progressWarnAfter` (also on a text-only stop), force-terminate at `progressForceAfter`. **Lever B** best-guess salvage on iter-limit / budget-exceeded / progress-force when nothing was written. Snapshots conversation to Redis every 5 iters via `ContextStore`. |
| `PatchAgent.java` | Patch-mode single-shot agent. Loads `prompts/patch-agent.md` — **mode-aware reproduce-first** (RL-2026-05-033): if a failing test/repro is in the spec (the `finding:*` surfaces) run it to see fail→fix→pass; if blind (benchmark / issue-only / existing-repo) write a scratch repro at `/tmp` (out of the diff), confirm fail→fix→pass→run existing tests. Replaced the old oracle "READ THE GOLD TESTS FIRST" prompt that contradicted blind specs. Per-provider iter caps (Anthropic 150, OpenAI 100, Gemini 120). Test-verification gate on `completeTask` (`failed:[]`, `errored:[]`, `exit_code:0` within `TEST_VERIFICATION_RECENCY_ITERS=5`) — **scoped by run source** (RL-2026-05-028): ON for `finding:*` autofix surfaces (the failing test IS the spec), OFF for blind `swebench*`/`benchmark*` runs (the target test is held out, so the gate could never pass → loop to iter cap). |

## Patterns

- **Native tool calling end-to-end.** No XML `<tool_call>` parsing in V2 — that was a V1 idiom. Strict JSON schemas on every `tool/` entry.
- **Sliding-window context:** first 2 + last 18 messages — applies to the legacy `FallbackLlmRouter` non-tool agents ONLY. The V2 `WorkerAgent` loop (`engine/`) keeps its FULL conversation history (no window); `ToolOutputCompactor` (default OFF, `worker.tool-compactor.enabled`) is the only worker-context compaction lever.
- **Token-cost control:** `readFile` 5k chars (full-file reads; range reads untruncated), `shell` / `buildProject` 6k chars inline (`ToolOutput.budget` — full log spilled to disk + a `readFile` path).
- **Never call providers directly** — go through `LlmRouter` (native tool agents) or `FallbackLlmRouter` (non-tool agents).
- **Worker progress signal (RL-2026-05-005):** ONE counter `itersSinceProgress` (consecutive iters with no `writeFile`/`editFile`) drives everything. At `progressWarnAfter` (per-tier `req.stagnationWarnAfter`, default `STAGNATION_WARN_AFTER_N=8`) inject ONE "PROGRESS CHECK" UserMessage — the same one-shot nudge also fires on a premature text-only stop (model emits a summary without calling `completeTask`). At `progressForceAfter` (default `STAGNATION_FORCE_AFTER_N=12`) force-terminate with `COMPLETED_BY_STAGNATION` (Lever B salvage first if nothing was written). UserMessage (not SystemMessage) so Gemini's implicit cache prefix stays intact. This replaced the old Lever A + Lever C + stagnation warn/force quartet.
- **gitCommit denied for the worker** — `ToolRegistry.bindForWorker(ctx)` filters it (auto-push happens at run-end via `ScmPushService.pushMultiRepo`).
- **Validation v3 Pillar 1:** `PlannerOutputUtils.validatePlan` enforces every spec requirement is cited by at least one task; one retry on violation. Gated behind `validation.v3-strict` (default OFF).
- **Prompts** in `src/main/resources/prompts/*.md`. Rollback archives `planner.v*.txt` + `reviewer-v2.txt` retained for `PromptVersioningService`.
