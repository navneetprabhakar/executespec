# `agent/` — LLM agents + routing

> Last reviewed: 2026-06-10 (1.0.0-M1).

All LLM-calling agents + the routing infrastructure for the V2 pipeline.

## Key files

| File | Purpose |
|------|---------|
| `LlmRouter.java` | Canonical native-tool-calling dispatcher. Routes Anthropic via Spring AI, Gemini via `GeminiNativeToolClient`, and OpenAI-wire providers through `OpenAiNativeToolClient` (OpenAI, OpenRouter, DeepSeek, Fireworks). OpenRouter calls include `provider.sort=latency` after the 2026-06-10 MiMo probe showed default price-routing was much slower for short VM/local calls. Every call flows through `RunCostTracker` (cache-aware pricing from `application.yml model-matrix.model-pricing`; OpenRouter literal route rows win before legacy owner-provider fallback). Goal-scoped live tests additionally require an exact provider/model/run reservation through `ProviderTestBudgetGuard`; ordinary Maven tests are transport-disabled. **Bounded same-provider retry** (RL-2026-05-029): up to 4 attempts, exponential backoff (2s/4s/8s), only on transient errors (5xx / connection reset / I/O timeout / 429 via `isTransientError`); permanent 4xx fail fast. Retries the SAME provider first to keep per-provider numbers honest + survive transient upstream blips. **Multi-provider failover (RL-2026-05-062, closes audit M#68, flag `router.failover.enabled`, V226, default OFF):** when the same-provider retry is exhausted on a transient error, `maybeFailover` walks the primary model's `ModelRegistry.fallbackChainFor` chain and tries each *different* provider once (each with its own transient retry). BYOK-safe — a run on a customer key only fails over to a provider the customer ALSO keyed (never silently to a platform key); DeepSeek/OpenRouter/Fireworks are never targets. Backoff sleep extracted to package-private `backoffSleep` so tests can no-op it. **`callText` is the migration seam for text-only callers:** it uses the same canonical transport, key resolution, usage accounting, retry/failover policy, and telemetry with an explicit empty tool list, so metadata-only calls do not bind worker tools. **`LlmRequest.toolChoice`** (RL-2026-05-059): nullable OpenAI-wire `tool_choice` override (`"auto"`/`"required"`/`"none"`) passed through to the OpenAI-wire clients (`callOpenAi`/`callOpenRouter`/`callDeepSeek`/`callFireworks`); Gemini ignores it. **Anthropic now honors it via `AnthropicForcedToolClient`** (RL-2026-05-059) — a single-turn low-level `AnthropicApi` bypass with `ToolChoiceAny` (Spring AI's `AnthropicChatOptions` can't set `tool_choice`); fail-safe fallthrough to `AnthropicChatModel` on any error. Used by the WorkerAgent forced-tool-choice salvage. **Temperature drop (RL-2026-06-051, refreshed 2026-07-02):** Opus 4.7+, Sonnet 5, and later Anthropic frontier families can reject `temperature`/`top_p`/`top_k` with a 400. `AnthropicModelOptions` owns the shared skip list + robust backtick-tolerant deprecation matcher; `callAnthropic` self-heals by retrying without temperature and caching newly observed model IDs, while direct legacy helpers use the same skip rule. Per-key Anthropic model defaults intentionally avoid `temperature` so Spring AI cannot merge it back into pinned Sonnet 5 calls. |
| `AnthropicModelOptions.java` | Shared Anthropic request-option guard. Pre-skips `temperature` for `claude-sonnet-5`, `claude-opus-4-7`, and `claude-opus-4-8` model families and recognizes Anthropic's backtick-wrapped "`temperature` is deprecated" 400. Used by `LlmRouter`, `FallbackLlmRouter`, system model config, testgen/API-test helpers, and accuracy assessment. |
| `AnthropicForcedToolClient.java` | **(RL-2026-05-059)** Forces an Anthropic tool call for the WorkerAgent Lever-B salvage when `LlmRequest.toolChoice="required"`. Bypasses `AnthropicChatModel` (no `tool_choice` in its options) → single-turn `AnthropicApi` POST with `ToolChoiceAny` + restricted tools (writeFile/editFile/completeTask) over a flattened transcript. Returns `null` on ANY failure → caller falls through, so it can't regress production Anthropic traffic + only runs on an already-failing zero-write salvage. |
| `FallbackLlmRouter.java` | **DEPRECATED (RL-2026-05-041) — no new callers; migrate to `LlmRouter.callText` where native tools are not required.** Legacy V1 router; still used by the remaining non-tool-calling agents (`AccuracyAssessmentService`, `ConversationAgent`, `testgen/*`, and other legacy evaluators). Multi-provider fallback via YAML `failover-order`. Emits `RUN_PROVIDER_SWITCHED` SSE on fallback. `FallbackMode.NO_FALLBACK` opts out (used when `-Dexecutespec.strict-provider=true`). The divergent retry/failover vs. `LlmRouter` (audit risk #10) is a transitional fork pending migration. `RunTitleSummarizer` and `ProjectBriefService` now use the canonical text seam. |
| `OpenAiNativeToolClient.java` | OpenAI-wire native-tool client — used by OpenAI, OpenRouter, DeepSeek, and Fireworks. Supports per-call `baseUrl`, `apiKey`, and `extraBody` so aggregators can receive provider-routing hints without forking client code. |
| `GeminiNativeToolClient.java` | Gemini native-tool client — schema sanitization + thought-signature round-trip; implicit-cache prefix preserved. **Explicit context caching** (RL-2026-05-059, flag `gemini.explicit-cache.enabled`, V225, default OFF): mints a `/v1beta/cachedContents` resource for the stable system+tools+toolConfig prefix, references it by name per call + OMITS those from the request body (Gemini 400s if `cachedContent` + system/tools/tool_config are both set) → prefix billed at the cache rate; keyed by SHA-256(model+systemText+toolsJson), fail-safe inline fallback on any mint/stale-cache 4xx. Records `cache_read_input_tokens` on every call. |
| `SmartClassifierAgent.java` | (LIGHTWEIGHT) Picks `PlanStrategy ∈ {SINGLE_SHOT, SMALL, MEDIUM, LARGE, LEGACY}`. Heuristic fast path (≤150-char tiny specs, no multi-feature keywords) returns at 0ms / $0; LLM verifier hits Haiku/Flash with the heuristic verdict as a hint. Redis cache 1h TTL keyed by `SHA-256(spec + sortedRepos + projectId)`. Always falls back to heuristic on parse / enum / timeout error. |
| `OutlinePlannerAgent.java` | (PLANNING) Two modes — `FULL_PLAN` (32k cap, single `submitPlan` tool call) for SMALL/MEDIUM; `SKELETON_ONLY` (8k cap, id/title/complexity/repos/dependsOn/type only) for LARGE/LEGACY. ## Patterns

- **Native tool calling end-to-end.** No XML `<tool_call>` parsing in V2 — that was a V1 idiom. Strict JSON schemas on every `tool/` entry.
- **Sliding-window context:** first 2 + last 18 messages — applies to the legacy `FallbackLlmRouter` non-tool agents ONLY. The V2 `WorkerAgent` loop (`engine/`) keeps its FULL conversation history (no window); `ToolOutputCompactor` (default OFF, `worker.tool-compactor.enabled`) is the only worker-context compaction lever.
- **Token-cost control:** `readFile` full reads cap at 60KB/2000 lines, **head-first** truncation at a line boundary (byte-exact from line 1 so `editFile` matches; range reads untruncated — RL-2026-05-062, was a 5KB head+tail-with-a-hole), `shell` / `buildProject` 6k chars inline (`ToolOutput.budget` — full log spilled to disk + a `readFile` path).
- **Never call providers directly** — go through `LlmRouter` (native tool agents) or `FallbackLlmRouter` (non-tool agents).
- **Worker progress signal (RL-2026-05-005):** ONE counter `itersSinceProgress` (consecutive iters with no `writeFile`/`editFile`) drives everything. At `progressWarnAfter` (per-tier `req.stagnationWarnAfter`, default `STAGNATION_WARN_AFTER_N=8`) inject ONE "PROGRESS CHECK" UserMessage — the same one-shot nudge also fires on a premature text-only stop (model emits a summary without calling `completeTask`). At `progressForceAfter` (default `STAGNATION_FORCE_AFTER_N=12`) force-terminate with `COMPLETED_BY_STAGNATION` (Lever B salvage first if nothing was written). UserMessage (not SystemMessage) so Gemini's implicit cache prefix stays intact. This replaced the old Lever A + Lever C + stagnation warn/force quartet.
- **gitCommit denied for the worker** — `ToolRegistry.bindForWorker(ctx)` filters it (auto-push happens at run-end via `ScmPushService.pushMultiRepo`).
- **Validation v3 Pillar 1:** `PlannerOutputUtils.validatePlan` enforces every spec requirement is cited by at least one task; one retry on violation. Gated behind `validation.v3-strict` (default OFF).
- **Prompts** in `src/main/resources/prompts/*.md` plus active `.txt` prompts loaded by specific non-tool agents. Dead rollback archives (`planner.v*.txt`, legacy `planner.txt`, `triage.txt`, `reviewer-v2.txt`) were removed in the 2026-07-02 prompt-audit cleanup; rollback uses `PromptAuditEntry.previousContent` and dynamically-created backups for live prompt files, not inert classpath archives.
