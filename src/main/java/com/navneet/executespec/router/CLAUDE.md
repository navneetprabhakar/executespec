# `router/` — Model selection + provider routing

> Last reviewed: 2026-06-10 (1.0.0-M1).

User-selected provider routing with YAML as the single source of truth and a Redis-backed circuit breaker.

> **Literals are illustrative — `application.yml model-matrix` is authoritative.** They drift; this table wrongly showed WORKHORSE = haiku/mini for months. WORKHORSE is the **flagship** tier ("keep flagship — worker is reasoning-heavy, +17pp on p30"), NOT a cheap model. **2026-07-02:** Anthropic PLANNING + WORKHORSE moved to Sonnet 5 through 2026-08-31 while introductory pricing is active; Sonnet 4.6 remains selectable. **RL-2026-06-052:** LIGHTWEIGHT re-tiered to a genuinely cheaper model per provider (anthropic→Haiku, openai→gpt-5.4-mini, gemini→gemini-3-flash-preview, openrouter→Haiku) for light agents. > ⚠️ **The WorkerAgent's ACTUAL model is COMPLEXITY-routed, not its `WORKHORSE` tier-map row.** `SequentialExecutor.tierConfigFor` re-resolves the worker by task complexity: **LOW→WORKHORSE by default, MEDIUM→WORKHORSE, HIGH→PLANNING**. LOW can opt into LIGHTWEIGHT through `execution.continuation.low-complexity-worker-start-tier=LIGHTWEIGHT` so a run can start cheap and rely on automatic continuation to step up. **`pipeline_run.worker_model` is the run-level DEFAULT and is MISLEADING** — the real per-task model lives only in the backend log (`WorkerAgent START ... model=X`). A whole eval campaign silently ran on the cheap tier this way (2026-06-02). A per-run `RunRequest.modelName` is a hard pin and blocks automatic route changes; use the LOW start-tier knob for cheap-start experiments that should still step up.

Default provider: **Anthropic** (changed from OpenAI in 1.0.0-M1). Users can still set a project default, but cross-surface client defaults now live on `app_user.preferred_ai_provider` (V242). Web, CLI, and VS Code write `GET/PUT /api/auth/me/provider-preference`; explicit request input wins and is remembered, omitted input resolves through the account preference before falling back to project/YAML defaults.

## Provider failover

Per `application.yml failover-order:`, when a provider fails the router walks the chain: `anthropic → openai → gemini`, `gemini → openai → anthropic`, `openai → gemini → anthropic`. `FailoverOrderEnumAlignmentTest` pins every failover-order entry and every `model-matrix.providers` key to a valid `LlmProvider` enum constant. `OPENROUTER`, `DEEPSEEK`, and `FIREWORKS` are intentionally NOT in any failover chain — they are explicit BYOK / operator routes that the operator/admin opted into, and silently switching off them would defeat the cost / data-residency / latency reason they picked them.

`FallbackLlmRouter` (**deprecated — RL-2026-05-041, no new callers; migrate text-only callers to `LlmRouter.callText`**) honours `FallbackMode.NO_FALLBACK` for callers that need strict provider isolation (used when `-Dexecutespec.strict-provider=true`). `RunTitleSummarizer` is the first migrated text-only caller; `callText` uses an explicit empty tool set so metadata calls do not bind worker tools.

## Circuit breaker

- **Storage:** Redis (`StringRedisTemplate`). Keys: `provider:health:{name}`, `provider:failures:{name}`.
- **Threshold:** 10 consecutive failures → OPEN. (Was documented as 5 — corrected by audit 2026-05-12 L #64.)
- **Recovery:** unhealthy key has 180s TTL → auto-expires → provider assumed healthy again.
- **Fail-open:** Redis errors degrade to "assume healthy" (never blocks LLM calls due to Redis issues).
- **Metrics:** `executespec.provider.circuit_opened`, `executespec.provider.circuit_closed` (tagged by provider).
- **Integration:** `FallbackLlmRouter` checks health before each provider attempt; records success/failure after each call. `LlmRouter` (V2 native-tool and `callText` path) owns bounded same-provider retry and flag-gated YAML-chain failover; both paths remain transport-disabled in ordinary tests.
