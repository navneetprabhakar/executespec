# `router/` — Model selection + provider routing

## Project route configuration errors (2026-08-02)

`ProjectProviderResolver` differentiates missing and invalid project providers.
`ModelResolver` uses `ModelMatrixConfigurationException` when matrix resolution is unavailable.
`ProjectRoutingException` translates these to stable structured 409/503 `errorCode` responses
before dispatch. Its message is customer-safe and never exposes the invalid stored value or matrix
cause.

> Last reviewed: 2026-08-03 (2.0.0).

User-selected provider routing with YAML as the single source of truth and a Redis-backed circuit breaker. V260 seeds the evidence-gated initial worker-route flag; keep it OFF until observed quality evidence is sufficient.

from silently choosing different provider defaults.

## Provider failover

Per `application.yml failover-order:`, when a provider fails the router walks the chain: `anthropic → openai → gemini`, `gemini → openai → anthropic`, `openai → gemini → anthropic`, and `deepseek → openrouter → fireworks`. Each target uses its equivalent planning/workhorse/lightweight model. A provider with no explicit entry has no cross-provider fallback and cannot inherit a generic tier chain. Native DeepSeek is always the first hop; OpenRouter and Fireworks are recovery hops only. `FailoverOrderEnumAlignmentTest` pins every failover-order entry and every `model-matrix.providers` key to a valid `LlmProvider` enum constant. BYOK runs cross only to providers for which the same customer/org has a key.

All text-only callers now use `LlmRouter.callText` (or `callTextStrict` when cross-provider failover is prohibited), with an explicit empty tool set so metadata calls do not bind worker tools. The former compatibility router was removed in ExecuteSpec 2.0; there is one provider transport, one retry/failover policy, and one usage ledger.

## Circuit breaker

- **Storage:** Redis (`StringRedisTemplate`). Keys: `provider:health:{name}`, `provider:failures:{name}`.
- **Threshold:** 10 consecutive failures → OPEN. (Was documented as 5 — corrected by audit 2026-05-12 L #64.)
- **Recovery:** unhealthy key has 180s TTL → auto-expires → provider assumed healthy again.
- **Fail-open:** Redis errors degrade to "assume healthy" (never blocks LLM calls due to Redis issues).
- **Metrics:** `executespec.provider.circuit_opened`, `executespec.provider.circuit_closed` (tagged by provider).
- **Integration:** `LlmRouter` (native-tool and `callText` paths) owns bounded same-provider retry and flag-gated YAML-chain failover; ordinary tests remain transport-disabled.

## Known tech debt

- ~~**Bug #1c**~~ — **mostly mitigated** (corrected 2026-05-24). `ModelResolver` gates adaptive routing behind two layers (`lookupModel`, lines 78-92): the `-Dexecutespec.strict-provider` JVM flag AND the `routing.adaptive-routing.enabled` feature flag (default OFF). With neither saying "let adaptive run" it always uses the user's provider — so a strict-locked caller is no longer silently switched. DeepSeek is additionally excluded from adaptive switching: a healthy native request must remain native, with OpenRouter then Fireworks reserved for ordered recovery. Explicit provider selection still wins. Residual debt: the switch is still silent (no log/event) for non-DeepSeek routes when an operator flips the flag ON, and there's no per-org opt-out.
