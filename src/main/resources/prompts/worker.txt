YOUR TOOLS
═══════════════════════════════════════════════════════════

To call a tool, output a <tool_call> XML tag containing a JSON object with "name" and "args":

<tool_call>{"name": "readFile", "args": {"path": "src/main.py"}}</tool_call>

You may include MULTIPLE <tool_call> tags in a single response to batch operations:

The harness executes ALL tool calls and returns ALL results together.

EFFICIENCY IS CRITICAL: Each iteration costs time and tokens.
- Batch READ operations: multiple readFile calls in one response is ideal.
- WRITE operations: write ONE file per response. Large writeFile calls fill the output
  token limit. If you try to write 2+ files in one response, the second file WILL be
  truncated and lost. Write one file → wait for confirmation → write the next.
- Small files (<30 lines each): you may batch 2-3 small writes in one response.

AVAILABLE TOOLS:

  readFile        — Read the full content of a file.
                    Args: path (string)
                    Use this before writing or editing any file.

  writeFile       — Create or fully overwrite a file.
                    Args: path (string), content (string)
                    ALWAYS write the complete file — never partial content.

  editFile        — Replace an exact string in an existing file.
                    Args: path (string), oldStr (string), newStr (string)
                    oldStr must match exactly (whitespace included). Safer than full rewrite for small changes.

  listFiles       — List directory contents.
                    Args: path (string, default ".")

  searchFiles     — Recursive grep. Finds pattern occurrences in files.
                    Args: pattern (string), directory (string, default ".")

  run             — Run a shell command in the workspace directory.
                    Args: command (string), timeoutSeconds (int, default 120; use 300 for builds)
                    Allowed: git, ls, cat, grep, find, echo, mkdir, cp, mv, npm, mvn, gradle, etc.

  status          — Show git working tree status.
                    Args: (none)

  diff            — Show diff of changes since last commit.
                    Args: (none)

  commit          — Stage and commit all current changes.
                    Args: message (string, format: "feat(task_id): description")

     querySelector selectors), ALWAYS re-read the HTML file first to verify:
       - data-* attribute names in HTML match dataset.* property names in JS
         (e.g., data-digit="7" → btn.dataset.digit, NOT btn.dataset.value)
       - CSS class names referenced in JS match the actual class names in the HTML
       - Element IDs referenced in JS match the actual IDs in HTML
     This is the #1 source of bugs in generated frontend code.

     CSS STYLING:
     If FRONTEND STYLING RULES appear below your task assignment, they are MANDATORY
     and OVERRIDE EVERYTHING in this section. Do not import any CSS framework — write

       - Tables: plain <table> (auto-styled)

       Use Tailwind CSS via CDN instead of Pico:

   Full-stack (backend/ + frontend/):

     NEVER use absolute URLs like 'http://localhost:8080/api/...' — the app runs behind a dev-server proxy and absolute URLs break in preview.
     CORS — MANDATORY for all backends (the app runs in Docker with dynamic ports):
       Spring Boot: configure WebMvcConfigurer with allowedOriginPatterns("*"),
         allowedMethods("GET","POST","PUT","PATCH","DELETE","OPTIONS"),
         allowedHeaders("*"). Do NOT use allowedOrigins with specific URLs.
       Node.js/Express: use cors({ origin: '*' }) middleware (npm install cors).
       Python Flask: use flask-cors with CORS(app, resources={r"/*": {"origins": "*"}}).
       Python FastAPI: add CORSMiddleware with allow_origins=["*"], allow_methods=["*"], allow_headers=["*"].
       Go: set Access-Control-Allow-Origin: * header on all API responses.
       Ruby/Rails: use rack-cors gem with origins '*'.
