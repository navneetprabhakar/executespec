REVIEW FLAGS — scan every file you read for these red flags across ALL seven axes:
  CORRECTNESS:    Spec mismatch? Missing edge case? Off-by-one? Wrong return type?
  READABILITY:    Deep nesting (>3 levels)? Cryptic names? Clever tricks over clarity?
  ARCHITECTURE:   Circular dependency? Business logic in controller? Wrong abstraction layer?
  SECURITY:       Unvalidated input? Hardcoded secret? Missing auth check? Raw SQL?
  PERFORMANCE:    N+1 query? Unbounded list fetch? Large object in hot path? Missing pagination?
  STUBS:          Any file with "COMPILER STUB" header or UnsupportedOperationException("STUB — not implemented")
                  is an unfinished placeholder — flag as CRITICAL and list its path.
                  Check .agent-context/stubs.json if it exists for a list of known stubs.
  DEPLOYABILITY:  Can this project actually build and run in a container?
    - package.json has valid "start" or "dev" script that starts the server
    - All imports/requires resolve to actual files or declared dependencies
    - Server binds to 0.0.0.0 (not just localhost) — required for Docker
    - Port configuration matches what the app expects (PORT env var used, not hardcoded)
    - No missing dependencies referenced in code but absent from package.json/pom.xml/requirements.txt
    - Static assets referenced in HTML (CSS, JS, images) actually exist in the workspace
    - Entry point file referenced in package.json "main" or Dockerfile CMD exists
A file that compiles and matches the spec can still fail on security, performance, or deployability.

**AI-Generated Code Anti-Patterns (flag these as issues):**
- Placeholder/stub implementations masked as real code: empty catch blocks, methods that just
  return null/empty/hardcoded values, "// TODO: implement" left in production code
- Copy-paste signatures that don't match the actual data model (e.g., method takes String id
  but the entity uses Long id, or field named "title" but entity has "name")
- Hallucinated imports: import statements for packages/classes that don't exist in the project
  or any declared dependency (common with AI — it invents plausible-sounding package names)
- Duplicate logic: same business logic implemented in both controller AND service layer,
  or same validation in both frontend AND backend with different rules
- Dead code: functions/methods defined but never called from anywhere, unused variables,
  commented-out code blocks left in as "examples"
- Overly verbose generated comments that just restate the code:
  BAD:  // Get the user by ID → User user = userService.getUserById(id);
  These add noise and indicate the AI padded output. Flag as MINOR.
- Missing error propagation: API calls that catch exceptions and return generic 500 instead
  of meaningful error responses with proper status codes
