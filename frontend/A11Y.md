# Accessibility — running checks locally

The round-3 persona audit (`docs/audits/persona-test-2026-05-01-r3.md`) flagged three WCAG-AA contrast failures that should never have shipped. Process gap: no automated check ran the contrast math against the live dark theme. This file documents the two checks that close that gap.

## 1. Token-level contrast regression (always-on)

`src/design-system/contrast.test.ts` pins WCAG-AA contrast ratios for every (token, surface) pair the audit fixed. Vitest-shape — runs as soon as vitest is wired into the frontend (an existing dormant test sits at `src/v3/lib/tierDisplay.test.ts`).

Until vitest is installed, the fixed-value design (no DOM, no CSS parsing) means the file documents the contract. Any palette tweak that shifts a hex must update **both** the CSS and the fixed value in `contrast.test.ts` so the test stays a true regression guard.

To enable:

```bash
cd frontend
npm install --save-dev vitest @vitest/ui jsdom
npx vitest run contrast
```

## 2. Live a11y crawl (manual / pre-merge)

`.pa11yci.json` runs pa11y-ci with both axe-core and HTML CodeSniffer against every public route. Catches:

- contrast violations (axe's SC 1.4.11 check has caught all three of the round-3 misses)
- missing alt text / link names / button names
- skipped heading levels
- aria-required attributes

To run:

```bash
cd frontend
npm install --save-dev pa11y-ci
npm run dev   # in one terminal; serve at :5173
npx pa11y-ci  # in another; reads .pa11yci.json
```

Auth-gated routes (`/projects`, `/v3/*`, `/admin`) aren't crawled yet — pa11y can't authenticate. Follow-up plan: a `pa11y-ci-auth.js` driver that primes a session cookie via puppeteer before invoking the crawler. Tracked in `docs/plans/a11y-coverage-plan.md` (TBD).

## 3. CI integration (TODO)

Neither check is wired into GitHub Actions yet. The token test (#1) is cheap (pure functions, no server) — that's the natural first thing to add. Pa11y-ci (#2) needs a CI runner that can spin up the dev server, which has knock-on cost.

Suggested order:

1. Install vitest + run `npx vitest run` in the existing frontend build job.
2. Add a separate `a11y-public.yml` workflow that boots the dev server in the background and runs pa11y-ci against the URL list above.
3. Wave 2: extend pa11y-ci to authenticated routes via the cookie-priming driver.

The audit report's "single most ROI-positive piece of CI tooling not yet in place" is #1 — small lift, catches the exact class of bug the round-3 batch fixed.
