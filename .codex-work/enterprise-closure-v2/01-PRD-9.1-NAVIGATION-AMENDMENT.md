# ExecuteSpec Enterprise — PRD §9.1 Navigation Amendment

Status: **Approved product-contract amendment for implementation planning**  
Authority basis: C01, C03, C14 and the approved Objective-centred Enterprise shell  
Amends: `ENTERPRISE-IMPLEMENTATION-PRD.md` §9.1 only

## Replacement text for PRD §9.1

ExecuteSpec Enterprise uses one Objective-centred shell:

`Organisation / Team → Objective → Inspect`

The six PRD destinations remain required product responsibilities but do not all become permanent peer navigation items. Their exact mapping is:

| PRD destination | Objective-centred mapping | Permanent surface? | Entry behavior |
|---|---|---:|---|
| Home | Left rail: Needs you, today’s ready work, active/recent Objectives | No separate full-time canvas | Default Enterprise landing state; selecting an item opens its Objective without changing product view |
| Objectives | Left rail Objective list, filters, create/link flow, lifecycle indicators | Yes — primary product context | Objective remains stable while center stages and Inspect content change |
| Intelligence | Purpose-built tool opened from semantic rail item or scoped Ask | Yes — global tool, not an Objective template | Defaults to current Objective scope when launched within an Objective; organisation scope is P1 and must be explicit |
| Services | Purpose-built portfolio/detail tool opened from semantic rail item or entity link | Yes — global tool, not an Objective template | Portfolio first, then service detail; live state is read-first and time-stamped |
| Evidence | Inspect within an Objective plus a cross-objective Evidence view reached from evidence links/filter | Contextual first; aggregate view as a tool | Objective evidence never loses objective/version/environment context; aggregate Evidence is not a separate testing product |
| Admin | Enterprise Settings opened from semantic rail item | Yes — administration workspace | Six groups: Organisation and people; Knowledge and context; Integrations; Governance and AI; Environments and operations; Billing and audit |

## Shell rules

1. The left pane contains organisation/team context, Needs you, Objective navigation, and the semantic entries for Intelligence, Services, and Settings.
2. The centre owns the current primary job: Objective stage, Intelligence query, service portfolio/detail, or Settings group.
3. The right pane is `Inspect`: evidence, context search, provenance, decision details, or action detail. It is contextual, collapsible, and absent by default when it does not materially support the job.
4. Both panes collapse and expand. Collapsed panes use semantic SVG icons, accessible names/tooltips, state indicators, and valid targets; never numbers or Unicode glyph strings.
5. Objective and Inspect input have distinct contracts. Objective input may clarify or propose typed work. Inspect search is read-only context retrieval and cannot mutate.
6. Verification is a stage/panel across Objective, Evidence, Service, PR/CI, CLI/IDE, and Settings; no top-level Verification app is added.
7. Studio and Enterprise use separate views and routes. A view switch carries only explicitly permitted references and re-authorises the target context.

## Maturity annotations

- P0: Objective-scoped Intelligence, selected-source Figma context, Slack notification/deep link, service/read-only operational context, GitHub/Bitbucket/Jira/Confluence/CI/preview at the declared matrix depth.
- P1: organisation-wide Intelligence, saved/shared queries, cross-team SME/overlap/flow, Slack query/actions, deeper graph traversal, PagerDuty/ServiceNow incident workflow.
- P2/Conditional: typed production remediation and rollback. P0/P1 may investigate, recommend, request approval, escalate, or hand off; they do not execute production mutation.

## Acceptance

- A coding agent can map every PRD destination to one exact shell responsibility without creating an extra permanent surface.
- All deep links resolve to the same Organisation/Team/Objective model and re-check permission.
- No P1/P2 feature is rendered as currently available without an implementation-status annotation.
- The amendment does not weaken the PRD rule that source systems remain authoritative.
